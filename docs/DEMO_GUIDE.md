## 2. Top 30 Viva Voce Questions & Model Answers

### Creational Patterns
**Q1: What is the Singleton pattern, and how did you ensure thread safety in SaveBite?**
> *Answer:* Singleton guarantees a class has only one instance and provides a global access point. In SaveBite, `ConfigManager` and `JwtKeyHolder` use double-checked locking with a `volatile` instance variable (or Bill Pugh inner static holder), ensuring safe publication across concurrent request threads without synchronization overhead on every read.

**Q2: What is the key difference between Factory Method and Abstract Factory?**
> *Answer:* Factory Method uses inheritance to defer instantiation of a single product to subclasses (e.g., `NotificationFactory` creating `ToastNotification` or `EmailNotification`). Abstract Factory uses object composition to produce entire families of related products (e.g., `ThemeFactory` creating matching `Button`, `Card`, and `Badge` components for Light or Dark theme) without coupling to concrete classes.

**Q3: Why use Builder instead of telescoping constructors for Listings and Orders?**
> *Answer:* `Order` and `Listing` entities contain over 8 attributes, many of which are optional (discounts, pickup addresses, gift packaging, tags). Telescoping constructors cause readability errors and parameter transposition bugs. `OrderBuilder` enforces fluent, step-by-step construction and validates business invariants prior to `build()`.

**Q4: How does the Prototype pattern work in SaveBite's 1-Click Reorder feature?**
> *Answer:* Instead of re-querying the database, parsing cart items, and rebuilding the object graph from scratch, `ReorderService` calls `order.clone()`. The clone creates a new instance with fresh order IDs, timestamps, and deep copies of line items, reducing database load and checkout latency.

### Structural Patterns
**Q5: How does the Adapter pattern differ from a Facade?**
> *Answer:* Adapter converts an incompatible existing interface into another interface the client expects (making two existing interfaces work together, such as adapting Google and GitHub OAuth client SDKs to `AuthProvider`). Facade defines a brand-new, simplified high-level interface over an entire complex subsystem (such as `CheckoutFacade` coordinating 6 services).

**Q6: How does the Bridge pattern solve the $M \times N$ class explosion in SaveBite's reports?**
> *Answer:* If we have 2 reports (`SalesReport`, `ImpactReport`) and 3 export formats (`Csv`, `Html`, `Pdf`), inheritance requires $2 \times 3 = 6$ classes (`SalesCsvReport`, `SalesPdfReport`, etc.). Bridge separates the abstraction hierarchy (`Report`) from the implementation hierarchy (`Exporter`), reducing the number of classes to $2 + 3 = 5$ and allowing independent extension.

**Q7: Explain the Composite pattern with SaveBite's "Rescue Bundles".**
> *Answer:* `CatalogNode` defines the common interface for single items (`ProductLeaf`) and collections (`Category`, `Bundle`). Clients can invoke `.getPrice()` or `.getWeightKg()` on a "Surplus Bakery Rescue Box" bundle, and the composite recursively computes the sum of its child leaves and sub-bundles without the caller needing `instanceof` checks.

**Q8: Why did you choose Decorator over subclassing for checkout pricing?**
> *Answer:* Subclassing for every combination of discount coupon, gift packaging, and express pickup would cause combinatorial class explosion (`GiftWrappedCouponOrder`, etc.). Decorators dynamically wrap `BasePrice` in any sequence at runtime (`new CouponDecorator(new GiftWrapDecorator(new BasePrice(100))))`.

**Q9: How does the Flyweight pattern optimize memory in the marketplace?**
> *Answer:* Surplus items display standard badges (`Vegan`, `Gluten-Free`, `Halal`). Instead of instantiating 10,000 separate badge objects across marketplace cards, `BadgeFactory` pools and returns only 6 immutable `BadgeFlyweight` instances holding intrinsic data (color, icon, label), dramatically reducing JVM heap footprint.

**Q10: What types of Proxies are used in SaveBite?**
> *Answer:* (1) **Virtual Proxy** (`LazyImageProxy`) defers loading high-resolution food images until requested. (2) **Protection Proxy** (`AdminServiceProxy`) validates user roles before delegating calls to `RealAdminService`. (3) **Caching Proxy** (`CachingListingRepositoryProxy`) stores catalog query results to prevent repetitive database reads.

### Behavioral Patterns
**Q11: How is Chain of Responsibility implemented in SaveBite's security pipeline?**
> *Answer:* Each inbound request traverses `RequestIdHandler -> RateLimitHandler -> JwtAuthenticationHandler -> BlacklistHandler -> RoleAuthorizationHandler`. Each handler inspects `SecurityContext`. If any condition fails (e.g. rate limit exceeded or token revoked), the handler terminates the chain with an HTTP status code, bypassing subsequent processing.

**Q12: How does the Command pattern enable Undo/Redo in the cart?**
> *Answer:* Every cart mutation (`AddToCartCommand`, `RemoveFromCartCommand`) implements `execute()` and `undo()`. `CommandHistory` maintains undo and redo stacks. When the user clicks "Undo", the top command is popped and its `undo()` method restores the previous cart state without clearing other items.

**Q13: How does the Interpreter pattern parse search queries like `price<100 AND category:bakery`?**
> *Answer:* The query string is tokenized into tokens (`price`, `<`, `100`, `AND`, `category`, `:`, `bakery`). The `Parser` constructs an Abstract Syntax Tree (AST) where terminal expressions (`ComparisonExpression`) evaluate individual listing attributes, and non-terminal expressions (`AndExpression`, `OrExpression`) combine results using boolean logic.

**Q14: Why use Iterator instead of returning standard `java.util.List` directly?**
> *Answer:* `ListingAggregate` provides specialized iteration behaviors: `PaginatedListingIterator` calculates windowed offsets and limits for server-side pagination, while `CarouselIterator` provides infinite circular looping (`next()` at the end wraps to the start, `previous()` at the start wraps to the end) without leaking internal storage.

**Q15: What problem does the Mediator pattern solve in the checkout form?**
> *Answer:* The checkout form has interdependent cascading fields: Country $\rightarrow$ State $\rightarrow$ City $\rightarrow$ Pickup Point $\rightarrow$ Time Slot $\rightarrow$ Payment Method. Without Mediator, each field would maintain direct references to 5 other fields ($O(N^2)$ couplings). `CheckoutMediator` centralizes change notifications, resetting or enabling dependent fields centrally.

**Q16: How does Memento achieve profile autosave without violating encapsulation?**
> *Answer:* `ProfileEditor` (Originator) creates a private, immutable `ProfileSnapshot` (Memento) containing its draft state. `SnapshotHistory` (Caretaker) stores the snapshots in a list. The Caretaker cannot read or alter snapshot internals; it only passes the memento back to `ProfileEditor.restore(memento)`.

**Q17: How is the Observer pattern used for real-time updates and Server-Sent Events?**
> *Answer:* `Subject` maintains a list of `Observer` instances. When a listing price drops or a cart item changes, `PriceDropSubject` calls `.update(event)` on `CartBadgeObserver`, `PriceDropAlertObserver`, and `PatternTracer`. The tracer streams the event immediately to open browser SSE connections (`/api/trace/stream`).

**Q18: What is the difference between State and Strategy patterns?**
> *Answer:* Both share similar class diagrams (Context delegating to an interface), but their **intent** differs:
> - **State:** Represents the changing internal lifecycle of an object (e.g., `FRESH -> DISCOUNTED -> SOLD`); state transitions occur automatically as a consequence of operations.
> - **Strategy:** Encapsulates interchangeable algorithms chosen by the client or context from the outside (e.g., choosing `ExpiryBasedDiscountStrategy` vs. `BulkBuyDiscountStrategy`), without state transitions.

**Q19: How does Template Method enforce the payment algorithm workflow?**
> *Answer:* `PaymentProcessor` defines the template method `processPayment()` as `final`, guaranteeing the invariant execution order: `validate() -> verifyInventory() -> executePayment() -> recordAudit() -> sendNotification()`. Subclasses (`CardPayment`, `UpiPayment`, `CodPayment`) override only `executePayment()` and `validate()`.

**Q20: Why did you use the Visitor pattern for calculating environmental impact?**
> *Answer:* The composite catalog contains nested `Category`, `Bundle`, and `ProductLeaf` elements. Using Visitor separates calculation algorithms from data structures: `ImpactVisitor` calculates CO2 savings, `WeightVisitor` computes food weight, and `TaxVisitor` calculates GST. New analytical operations can be added without modifying the catalog entity classes.

### Architectural & Security Questions
**Q21: Why was Javalin chosen over Spring Boot?**
> *Answer:* Spring Boot relies on heavy annotations, auto-configuration, and runtime reflection that conceal pattern mechanics behind framework magic. Javalin 6 is a lightweight, unopinionated web library on embedded Jetty. Every pattern (Chain of Responsibility pipeline, Proxy security, Singleton config) remains explicitly visible, readable, and debuggable in plain Java code.

**Q22: How is the JWT access token and refresh token security implemented?**
> *Answer:* Short-lived access tokens (15-minute lifespan) are stored **only in browser memory** (JavaScript variables), preventing XSS token theft from localStorage. Long-lived refresh tokens (7-day lifespan) are stored in an `HttpOnly`, `SameSite=Strict` cookie, rotated on every refresh call. When users log out, the token ID (`jti`) is added to the in-memory `BlacklistHandler` until expiration.

**Q23: How does SaveBite guarantee that the code and the design pattern documentation never drift?**
> *Answer:* `patterns.json` serves as the single source of truth. Every participating Java class is annotated with `@DesignPattern(name, role, description)`. The automated test `PatternConsistencyTest` scans all classes and validates them against `patterns.json`, failing the build if any pattern, file path, or class reference drifts.

**Q24: What is the purpose of the Live Pattern Trace console?**
> *Answer:* It provides empirical proof of design pattern execution during live demonstrations. Using Server-Sent Events (SSE), every pattern invocation publishes a `TraceEvent` with timestamp, pattern name, class, method, and message, rendered live in the collapsible UI drawer.

**Q25: Can an unauthenticated user access admin endpoints? Show how the architecture blocks this.**
> *Answer:* No. The request enters `SecurityFilter` $\rightarrow$ `SecurityPipeline`. `JwtAuthenticationHandler` marks the context unauthenticated because no valid Bearer token exists. `RoleAuthorizationHandler` detects `/api/admin/...`, intercepts the unauthenticated context, and immediately terminates the chain with `401 Unauthorized` (or `403 Forbidden` if role is not `ADMIN`), returning a structured JSON error shape.
